# AVRmusic

Собственный музыкальный сервис: сайт + Android-приложение (PWA / Trusted Web Activity).
Поиск, стриминг, скачивание, плейлисты, лайки, история, рекомендации, синхронизированные тексты,
канвасы (зацикленное видео за треком, как в Spotify), офлайн-режим, импорт по ссылкам и из папки.

| Веб (десктоп) | Android / мобильный |
|---|---|
| Главная с подборками, «Сейчас играет» с канвасом и текстом, альбомы, исполнители, плейлисты, админка | Нижняя навигация, полноэкранный плеер с канвасом, управление с экрана блокировки, офлайн-треки |

## Возможности

**Слушателю**
- Поиск по трекам, альбомам, исполнителям и плейлистам (FTS5, подсказки, поиск по префиксу, кириллица).
- Стриминг с перемоткой (HTTP Range), очередь, shuffle, repeat, скорость, таймер сна, горячие клавиши.
- Полноэкранный режим «Сейчас играет»: канвас (видео/анимация), синхронизированный текст с подсветкой строки
  и переходом по клику, очередь с перетаскиванием.
- Плейлисты: создание, редактирование, обложка, публичные/приватные, подписка на чужие, добавление из поиска.
- Лайки треков/альбомов/исполнителей/плейлистов, «Любимые треки», история прослушиваний, статистика профиля.
- Рекомендации «Подобрано для вас» (по лайкам и истории), «Радио трека», новые релизы, жанры.
- Скачивание: отдельный трек, альбом или плейлист одним ZIP-архивом; сохранение треков **офлайн** в браузере
  (IndexedDB), раздел «Загрузки» работает без сети.
- PWA: установка на телефон/десктоп, кэш интерфейса, Media Session (управление на экране блокировки и в
  наушниках), тёмная/светлая тема, русский/английский интерфейс.

**Администратору**
- Загрузка файлов через браузер (MP3, FLAC, M4A/AAC, OGG/Opus, WAV…): теги, встроенные обложки и тексты
  читаются автоматически; рядом с файлом подхватываются `cover.jpg`, `<имя>.lrc`, `<имя>.txt`, `<имя>.canvas.mp4`.
- Сканирование существующей коллекции (`MUSIC_DIR`) без копирования файлов.
- Импорт по ссылке через **yt-dlp**: YouTube, SoundCloud, Bandcamp, плейлисты, прямые ссылки — аудио в библиотеку
  или видео (mp4) для скачивания, с прогрессом и логом.
- Автоподбор синхронизированных текстов через открытый API **LRCLIB** (по одному треку или для всей библиотеки).
- Редактор трека: метаданные, участники, обложка, текст (LRC/plain), канвас; управление пользователями; статистика.

## Быстрый старт (разработка)

```bash
pnpm install
cp apps/api/.env.example apps/api/.env      # при желании поправьте JWT_SECRET и пути
pnpm seed                                    # демо-данные: admin/admin123, demo/demo123
pnpm dev                                     # API http://localhost:8080 + Vite http://localhost:5173
```

Откройте <http://localhost:5173>. Без seed первый зарегистрированный пользователь становится администратором.

Полезные команды:

| Команда | Что делает |
|---|---|
| `pnpm build` | собирает shared, веб-клиент и API |
| `pnpm start` | запускает собранный API, который отдаёт и веб-клиент (один порт) |
| `pnpm scan /path/to/music` | импортирует папку с музыкой (файлы остаются на месте) |
| `pnpm seed --force` | добавляет демо-данные поверх существующих |
| `pnpm test` | интеграционные тесты API (регистрация, загрузка, поиск, Range-стриминг, ZIP, тексты, канвасы, плейлисты) |

## Запуск в Docker

```bash
cp apps/api/.env.example .env      # docker compose читает переменные из корневого .env
docker compose up -d --build
```

Образ содержит `ffmpeg` и `yt-dlp`, поэтому импорт по ссылке и перекодирование работают «из коробки».
Тома: `./data` (база SQLite), `./media` (треки, обложки, канвасы), `./music` (коллекция для сканирования, только чтение).

## Схема «сервис на одном сервере, хранилище на вашем ПК»

База данных SQLite маленькая и должна лежать **рядом с API** (`DATA_DIR`), а вот медиафайлы могут находиться
где угодно — переменная `MEDIA_DIR` (и `MUSIC_DIR`) принимает любой путь, в том числе сетевое монтирование.
Рекомендуемая связка:

1. **Сеть.** Поставьте [Tailscale](https://tailscale.com) (или WireGuard) на сервер и на ПК — получите прямой
   защищённый канал без проброса портов и белого IP у ПК.
2. **Раздача диска с ПК.** Любой из вариантов:
   * Windows: общая папка (SMB) → на сервере `mount -t cifs //100.x.y.z/avrmusic /mnt/pc -o user=...,uid=1000`;
   * Linux/Windows/macOS: `rclone serve sftp` или `rclone serve webdav` на ПК → на сервере
     `rclone mount pc:avrmusic /mnt/pc --vfs-cache-mode full --daemon`;
   * Linux: NFS-экспорт или `sshfs user@100.x.y.z:/data/avrmusic /mnt/pc -o reconnect,ServerAliveInterval=15`.
3. **Настройка.** В `.env` сервера:
   ```
   DATA_DIR=/var/lib/avrmusic          # база, локальный диск
   MEDIA_DIR=/mnt/pc/avrmusic/media    # треки/обложки/канвасы — на ПК
   MUSIC_DIR=/mnt/pc/music             # существующая коллекция для сканирования
   ```
   В Docker — то же самое через тома: `- /mnt/pc/avrmusic/media:/media` и `- /mnt/pc/music:/music:ro`.
4. Загружаемые через админку и импортированные по ссылке файлы будут сразу писаться на ПК; стриминг идёт
   через сервер (он читает файл с монтирования и отдаёт клиенту с поддержкой Range).

Примечания: `rclone mount` с `--vfs-cache-mode full` даёт локальный кэш на сервере, что сглаживает нестабильный
домашний канал; при выключенном ПК сервис продолжает работать, но треки, которых нет в кэше, будут недоступны
(поиск, плейлисты и уже сохранённые офлайн-треки на телефоне работают).

## Переменные окружения

См. `apps/api/.env.example`. Главное:

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | секрет для токенов, **обязательно** смените в проде |
| `PUBLIC_URL` | публичный адрес (https://music.example.com) |
| `DATA_DIR` / `MEDIA_DIR` / `MUSIC_DIR` | база и временные файлы / медиа / коллекция для сканирования |
| `ALLOW_REGISTRATION` | разрешить регистрацию (первый пользователь всегда админ) |
| `PUBLIC_LIBRARY` | гости могут слушать без входа (скачивание/лайки всё равно требуют аккаунт) |
| `MAX_UPLOAD_MB` | лимит одного файла при загрузке |
| `YTDLP_PATH`, `FFMPEG_PATH` | пути к бинарникам для импорта по ссылке |
| `LRCLIB_URL` | сервер текстов (по умолчанию публичный https://lrclib.net, можно поднять свой) |
| `ANDROID_PACKAGE`, `ANDROID_SHA256` | Digital Asset Links для Android-приложения |

За реверс-прокси (nginx, Caddy, Traefik) включите HTTPS — без него не работают PWA-установка, Media Session
и TWA. Пример Caddy: `music.example.com { reverse_proxy 127.0.0.1:8080 }`.

## Android-приложение

Веб-клиент — полноценное PWA (иконки, manifest, service worker, офлайн). Готовый APK/AAB собирается из него
через Bubblewrap (Trusted Web Activity) — инструкция и конфиг в [`android/`](android/README.md).
Тонкая оболочка: интерфейс обновляется вместе с сервером, пересобирать приложение не нужно.

## Откуда брать музыку

Сервис — ваша личная библиотека, каталог наполняете вы. Поддерживаемые источники:

* собственные файлы (покупки в FLAC на Bandcamp/Qobuz, рипы своих дисков, свои записи) — загрузка или сканирование папки;
* импорт по ссылке через yt-dlp: ролики и плейлисты YouTube, треки и ремиксы SoundCloud, Bandcamp, прямые ссылки на файлы;
* каталоги с открытыми лицензиями: Jamendo, Free Music Archive, ccMixter и т.п.

Инструменты, снимающие защиту со стриминговых сервисов (Deezer/Tidal/Spotify-рипперы), в проект не входят и не
поддерживаются. Загружайте только контент, на который у вас есть права.

## Архитектура

```
apps/api      Fastify 5 + better-sqlite3 (FTS5) + music-metadata + archiver, JWT (access/refresh/media),
              HTTP Range стриминг, ZIP-выгрузка, импорт (upload / scan / yt-dlp), LRCLIB, очередь задач
apps/web      React 19 + Vite 7 + Tailwind 4 + TanStack Query + Zustand, vite-plugin-pwa (Workbox),
              IndexedDB (idb) для офлайн-треков, Media Session API
packages/shared  общие TypeScript-типы контракта API
android/      конфиг Bubblewrap для TWA
```

Основные эндпоинты (все под `/api`): `auth/*`, `home`, `search`, `tracks/:id` (+ `/lyrics`, `/radio`),
`albums`, `artists`, `genres`, `stream/:id`, `download/:id`, `download/album/:id`, `download/playlist/:id`,
`canvas/:id`, `playlists/*`, `me/likes/*`, `me/plays`, `me/history`, `me/stats`, `admin/*`
(upload, scan, import/url, lyrics/fetch-missing, tracks, albums, artists, users, stats).
Для `<audio>`/`<video>` используется отдельный долгоживущий media-токен в параметре `?t=`, чтобы перемотка
не ломалась при истечении короткого access-токена.
