# AVRmusic

Собственный музыкальный сервис: сайт + Android-приложение (PWA / Trusted Web Activity).
Поиск, стриминг, скачивание, плейлисты, лайки, история, рекомендации, синхронизированные тексты,
канвасы (зацикленное видео за треком, как в Spotify), офлайн-режим, импорт по ссылкам и из папки.

| Веб (десктоп) | Android / мобильный |
|---|---|
| Главная с подборками, «Сейчас играет» с канвасом и текстом, альбомы, исполнители, плейлисты, админка | Нижняя навигация, полноэкранный плеер с канвасом, управление с экрана блокировки, офлайн-треки |

## Возможности

**Слушателю**
- Поиск по трекам, альбомам, исполнителям и плейлистам (FTS5, подсказки, поиск по префиксу, кириллица).
- Стриминг с перемоткой (HTTP Range), очередь, shuffle, repeat, скорость, таймер сна, горячие клавиши.
- Полноэкранный режим «Сейчас играет»: канвас (видео/анимация), синхронизированный текст с подсветкой строки
  и переходом по клику, очередь с перетаскиванием.
- Плейлисты: создание, редактирование, обложка, публичные/приватные, подписка на чужие, добавление из поиска.
- Лайки треков/альбомов/исполнителей/плейлистов, «Любимые треки», история прослушиваний, статистика профиля.
- Рекомендации «Подобрано для вас» (по лайкам и истории), «Радио трека», новые релизы, жанры.
- Скачивание: отдельный трек, альбом или плейлист одним ZIP-архивом; сохранение треков **офлайн** в браузере
  (IndexedDB), раздел «Загрузки» работает без сети.
- PWA: установка на телефон/десктоп, кэш интерфейса, Media Session (управление на экране блокировки и в
  наушниках), русский/английский интерфейс.
- **Material 3 Expressive**: интерфейс собран на настоящих MD3-компонентах (библиотека
  [M3E](https://github.com/matraic/m3e): Navigation Rail/Bar, App Bar, FAB, кнопки с shape-morphing, чипы, слайдеры,
  диалоги, меню, bottom sheet, wavy-прогресс, snackbar, иконки Material Symbols). Динамический цвет Material You:
  палитра генерируется из сид-цвета или **из обложки играющего трека**, девять вариантов схем (Expressive, Vibrant,
  Tonal Spot, Fidelity, Content, Rainbow, Fruit Salad, Neutral, Monochrome), светлая/тёмная/авто, уровни контраста.

**Каталог и автоматическое пополнение (для себя и друзей)**
- Второй режим поиска — **«Каталог»**: мировой каталог исполнителей, альбомов и треков (метаданные Deezer public API,
  без ключа): страницы исполнителей с дискографией, синглами, сборниками, участием в чужих треках (фиты), похожими
  исполнителями, обложками и 30-секундными превью.
- Кнопка **«+»** у трека, **«Добавить альбом»** или **«Скачать всю дискографию»** ставит задачу в очередь. Дискография —
  это всё: альбомы, EP, синглы, свои треки со сборников и фиты у других исполнителей; альбомные версии качаются
  первыми, а тот же трек из сингла (тот же ISRC) пропускается как дубль. Сольная версия песни и версия «feat. …» —
  разные треки, обе добавляются. Сервер
  опрашивает **все настроенные источники параллельно** (YouTube и SoundCloud через yt-dlp, Audius, Internet Archive,
  Jamendo), оценивает кандидатов по названию, исполнителю, длительности, официальным «Topic»-каналам и качеству
  (lossless получает бонус), скачивает лучший, а при ошибке пробует следующего. Трек заводится с обложкой, годом,
  жанром, номером, фитами и текстом из LRCLIB. Ненадёжные совпадения (live, cover, remix, другая длительность) отклоняются.
- **Канвас сам находится**: после добавления трека сервер ищет официальный клип на YouTube (отсеивая lyric-видео,
  live, каверы и audio-only загрузки), скачивает ~10 секунд из середины, кадрирует в 9:16 и сохраняет как канвас.
  Для уже имеющихся треков: пункт «Найти канвас» в меню трека, кнопка в редакторе трека и «для всех треков» в админке.
- Уже имеющиеся треки помечаются «В библиотеке»; локальные страницы ссылаются на каталог и обратно.
- Очередь с прогрессом и логом — в разделе «Загрузки → Очередь загрузки на сервер» и индикатором в шапке. Очередь
  хранится в базе: после перезапуска или обновления сервера незавершённые задачи продолжаются сами.
- Регистрация только по одноразовым кодам приглашения: администратор создаёт код в админке («Пользователи»),
  отправляет другу код или ссылку, после регистрации код сгорает. Права на пополнение — `ACQUIRE_ROLE`
  (все / только админ / выкл).

**Администратору**
- Загрузка файлов через браузер (MP3, FLAC, M4A/AAC, OGG/Opus, WAV…): теги, встроенные обложки и тексты
  читаются автоматически; рядом с файлом подхватываются `cover.jpg`, `<имя>.lrc`, `<имя>.txt`, `<имя>.canvas.mp4`.
- Сканирование существующей коллекции (`MUSIC_DIR`) без копирования файлов.
- Импорт по ссылке через **yt-dlp**: YouTube, SoundCloud, Bandcamp, плейлисты, прямые ссылки — аудио в библиотеку
  или видео (mp4) для скачивания, с прогрессом и логом.
- Автоподбор синхронизированных текстов через открытый API **LRCLIB** (по одному треку или для всей библиотеки).
- Редактор трека: метаданные, участники, обложка, текст (LRC/plain), канвас; управление пользователями; статистика.

## Быстрый старт (разработка)

```bash
pnpm install
cp apps/api/.env.example apps/api/.env      # при желании поправьте JWT_SECRET и пути
pnpm seed                                    # демо-данные: admin/admin123, demo/demo123
pnpm dev                                     # API http://localhost:8080 + Vite http://localhost:5173
```

Откройте <http://localhost:5173>. Без seed первый зарегистрированный пользователь становится администратором.

Полезные команды:

| Команда | Что делает |
|---|---|
| `pnpm build` | собирает shared, веб-клиент и API |
| `pnpm start` | запускает собранный API, который отдаёт и веб-клиент (один порт) |
| `pnpm scan /path/to/music` | импортирует папку с музыкой (файлы остаются на месте) |
| `pnpm seed --force` | добавляет демо-данные поверх существующих |
| `pnpm test` | интеграционные тесты API (регистрация, загрузка, поиск, Range-стриминг, ZIP, тексты, канвасы, плейлисты) |

## Запуск в Docker

```bash
cp apps/api/.env.example .env      # docker compose читает переменные из корневого .env
docker compose up -d --build
```

Образ содержит `ffmpeg` и `yt-dlp`, поэтому импорт по ссылке и перекодирование работают «из коробки».
Тома: `./data` (база SQLite), `./media` (треки, обложки, канвасы), `./music` (коллекция для сканирования, только чтение).

## Схема «сервис на одном сервере, хранилище на вашем ПК»

База данных SQLite маленькая и должна лежать **рядом с API** (`DATA_DIR`), а вот медиафайлы могут находиться
где угодно — переменная `MEDIA_DIR` (и `MUSIC_DIR`) принимает любой путь, в том числе сетевое монтирование.
Рекомендуемая связка:

1. **Сеть.** Поставьте [Tailscale](https://tailscale.com) (или WireGuard) на сервер и на ПК — получите прямой
   защищённый канал без проброса портов и белого IP у ПК.
2. **Раздача диска с ПК.** Любой из вариантов:
   * Windows: общая папка (SMB) → на сервере `mount -t cifs //100.x.y.z/avrmusic /mnt/pc -o user=...,uid=1000`;
   * Linux/Windows/macOS: `rclone serve sftp` или `rclone serve webdav` на ПК → на сервере
     `rclone mount pc:avrmusic /mnt/pc --vfs-cache-mode full --daemon`;
   * Linux: NFS-экспорт или `sshfs user@100.x.y.z:/data/avrmusic /mnt/pc -o reconnect,ServerAliveInterval=15`.
3. **Настройка.** В `.env` сервера:
   ```
   DATA_DIR=/var/lib/avrmusic          # база, локальный диск
   MEDIA_DIR=/mnt/pc/avrmusic/media    # треки/обложки/канвасы — на ПК
   MUSIC_DIR=/mnt/pc/music             # существующая коллекция для сканирования
   ```
   В Docker — то же самое через тома: `- /mnt/pc/avrmusic/media:/media` и `- /mnt/pc/music:/music:ro`.
4. Загружаемые через админку и импортированные по ссылке файлы будут сразу писаться на ПК; стриминг идёт
   через сервер (он читает файл с монтирования и отдаёт клиенту с поддержкой Range).

Примечания: `rclone mount` с `--vfs-cache-mode full` даёт локальный кэш на сервере, что сглаживает нестабильный
домашний канал; при выключенном ПК сервис продолжает работать, но треки, которых нет в кэше, будут недоступны
(поиск, плейлисты и уже сохранённые офлайн-треки на телефоне работают).

## Переменные окружения

См. `apps/api/.env.example`. Главное:

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | секрет для токенов, **обязательно** смените в проде |
| `PUBLIC_URL` | публичный адрес (https://music.example.com) |
| `DATA_DIR` / `MEDIA_DIR` / `MUSIC_DIR` | база и временные файлы / медиа / коллекция для сканирования |
| `ALLOW_REGISTRATION` | разрешить регистрацию (первый пользователь всегда админ) |
| `PUBLIC_LIBRARY` | гости могут слушать без входа (скачивание/лайки всё равно требуют аккаунт) |
| `MAX_UPLOAD_MB` | лимит одного файла при загрузке |
| `CATALOG_ENABLED`, `DEEZER_API` | глобальный каталог метаданных (Deezer public API) |
| `ACQUIRE_ROLE` | кто может пополнять библиотеку из каталога (`user`/`admin`/`off`) |
| `ACQUIRE_SOURCES` | источники аудио по приоритету: `youtube,audius,archive,soundcloud,jamendo` |
| `JAMENDO_CLIENT_ID`, `AUDIUS_APP_NAME` | ключ Jamendo (бесплатный) и имя приложения для Audius |
| `YTDLP_PATH`, `FFMPEG_PATH` | пути к бинарникам для импорта по ссылке и из каталога |
| `LRCLIB_URL` | сервер текстов (по умолчанию публичный https://lrclib.net, можно поднять свой) |
| `CANVAS_AUTO`, `CANVAS_SECONDS` | автоканвасы: для треков из каталога находится официальный клип на YouTube и вырезается вертикальный отрезок (по умолчанию 9 с) |
| `ANDROID_PACKAGE`, `ANDROID_SHA256` | Digital Asset Links для Android-приложения |

За реверс-прокси (nginx, Caddy, Traefik) включите HTTPS — без него не работают PWA-установка, Media Session
и TWA. Пример Caddy: `music.example.com { reverse_proxy 127.0.0.1:8080 }`.

## Android-приложение

Веб-клиент — полноценное PWA (иконки, manifest, service worker, офлайн). Готовый APK (Trusted Web Activity)
собирается автоматически и публикуется в **GitHub Releases**: workflow `android.yml` хранит ключ подписи на сервере,
прописывает его отпечаток в `assetlinks.json` сайта и выкладывает `AVRmusic-<версия>.apk`. Проект и инструкция —
в [`android/`](android/README.md). Тонкая оболочка: интерфейс обновляется вместе с сервером, пересобирать
приложение нужно только при смене иконки, имени или домена.

## Откуда берётся музыка

1. **Каталог + автоподбор** (главный сценарий): ищете исполнителя или трек во вкладке «Каталог», жмёте «+».
   Метаданные, обложки и дискографии — из Deezer public API. Аудио ищется сразу в нескольких источниках:
   * **YouTube / YouTube Music** через yt-dlp — максимальный охват, официальные «Topic»-релизы, Opus/AAC до ~256 kbps;
   * **Audius** — открытая платформа независимых артистов, ремиксов и DJ-сетов, MP3 320 или оригинал (публичный API);
   * **Internet Archive** — нетлейблы, Live Music Archive, public domain, часто FLAC (публичный API);
   * **SoundCloud** через yt-dlp — ремиксы и релизы артистов;
   * **Jamendo** — Creative Commons, нужен бесплатный `JAMENDO_CLIENT_ID`.
   Порядок приоритета задаётся `ACQUIRE_SOURCES`. Тексты — LRCLIB.
2. **Импорт по ссылке**: конкретный ролик, трек, плейлист или альбом на YouTube, SoundCloud, Bandcamp, прямая ссылка.
3. **Свои файлы**: загрузка через админку или сканирование папки (FLAC-покупки с Bandcamp/Qobuz, рипы своих дисков,
   собственные записи) — единственный путь к lossless-качеству.
4. Каталоги с открытыми лицензиями: Jamendo, Free Music Archive, ccMixter и т.п.

Инструменты, снимающие защиту со стриминговых сервисов (Deezer/Tidal/Spotify-рипперы) и торрент-трекеры в проект
не входят. Загружайте только контент, на который у вас есть права.

## Архитектура

```
apps/api      Fastify 5 + better-sqlite3 (FTS5) + music-metadata + archiver, JWT (access/refresh/media),
              HTTP Range стриминг, ZIP-выгрузка, импорт (upload / scan / yt-dlp), LRCLIB, очередь задач
apps/web      React 19 + Vite 7 + Tailwind 4 + TanStack Query + Zustand, vite-plugin-pwa (Workbox),
              IndexedDB (idb) для офлайн-треков, Media Session API
packages/shared  общие TypeScript-типы контракта API
android/      конфиг Bubblewrap для TWA
```

Основные эндпоинты (все под `/api`): `auth/*`, `home`, `search`, `catalog/search`, `catalog/artists/:id`,
`catalog/albums/:id`, `catalog/acquire`, `catalog/jobs`, `tracks/:id` (+ `/lyrics`, `/radio`),
`albums`, `artists`, `genres`, `stream/:id`, `download/:id`, `download/album/:id`, `download/playlist/:id`,
`canvas/:id`, `playlists/*`, `me/likes/*`, `me/plays`, `me/history`, `me/stats`, `admin/*`
(upload, scan, import/url, lyrics/fetch-missing, tracks, albums, artists, users, stats).
Для `<audio>`/`<video>` используется отдельный долгоживущий media-токен в параметре `?t=`, чтобы перемотка
не ломалась при истечении короткого access-токена.

## Развёртывание на сервере (домен + HTTPS)

Вариант 1 — репозиторий приватный (по умолчанию): в настройках репозитория на GitHub добавьте secrets
`SERVER_HOST`, `SERVER_USER`, `SERVER_PASSWORD` (или `SERVER_SSH_KEY`) и variable `DOMAIN`. Workflow
`.github/workflows/deploy.yml` сам копирует код на сервер и запускает установщик при каждом push (или вручную
через «Run workflow»). Серверу доступ к репозиторию не нужен.

Вариант 2 — репозиторий публичный: одна команда под root на чистом Ubuntu/Debian (ставит Docker, клонирует
репозиторий, поднимает AVRmusic и HTTPS-прокси):

```bash
curl -fsSL https://raw.githubusercontent.com/avtohauser/AVRmusic/claude/music-service-streaming-nfpgvx/deploy/install.sh | bash -s -- music.avthsr.space
```

Скрипт создаст `/opt/avrmusic/.env` (случайный `JWT_SECRET`), данные положит в
`/srv/avrmusic/{data,media,music}`. Первый зарегистрированный аккаунт — администратор; остальные регистрируются
только по одноразовым кодам, которые он создаёт в админке.

Реверс-прокси выбирается автоматически (переменная `PROXY` в `.env`):

* порты 80/443 свободны → `PROXY=caddy`: Caddy с автоматическим HTTPS;
* на сервере уже работает nginx с другими сайтами → `PROXY=nginx`: приложение публикуется только на
  `127.0.0.1:APP_PORT`, в nginx добавляется один файл `avrmusic.conf` для домена (остальные сайты не меняются),
  сертификат Let's Encrypt выдаёт certbot (webroot) и продлевает по таймеру. Перед `reload` выполняется `nginx -t`;
  при ошибке наш конфиг удаляется, nginx остаётся как был.

Обновление:

```bash
cd /opt/avrmusic && git pull && docker compose -f docker-compose.prod.yml up -d --build
```

Хранилище на вашем ПК подключается так же, как описано выше: смонтируйте диск и укажите `MEDIA_PATH` в `.env`.
