# AVR ecosystem — правила для агента

Подробный бриф, карта репозитория, сервер и список задач — [`docs/handoff/README.md`](docs/handoff/README.md).
Прочитай его целиком перед первой задачей. Бренд — звезда и «avr» с припиской продукта: брендбук
https://claude.ai/artifact/Tr7U7AEggQj5D5BoTuPvfQ (в репозитории `brand/index.html`, кратко — [`brand/README.md`](brand/README.md)),
файлы — `brand/assets/` (генерируются `brand/tools/`, руками не правятся).

## Пользователь

- Отвечай **по-русски**. Вопросы приветствуются: где неясно, что и как переделать, — спроси, а не угадывай.
- Сервис частный: пользователь и 2–3 друга. Регистрация только по приглашениям, администратор — только пользователь.
- После сборки APK давай ссылку: https://github.com/avtohauser/AVRmusic/releases/latest. IPA собирай только по просьбе.

## Безопасность — без исключений

- **Репозиторий публичный.** В код, коммиты, релизы, логи CI и issues не попадают: IP-адреса, пароли, токены, ключи,
  cookies, `.env`, личные данные, конфиги и исходники бэкендов с сервера (даже зашифрованные).
- **Никогда не проси вставить пароль, токен или ключ в чат.** Доступы — через SSH-ключ на ПК, GitHub Secrets
  (`SERVER_HOST`, `SERVER_USER`, `SERVER_PASSWORD`/`SERVER_SSH_KEY`, `STORAGE_HOST`, `STORAGE_PASSWORD`, var `DOMAIN`)
  или админку сервиса. Не выводи секреты в терминал (`cat .env`, `env`, `docker inspect` с переменными — нельзя).
- Cookies YouTube, ключи Spotify, Telegram-бота, Last.fm, Telegram API — только в админке/БД сервиса, клиентам не отдаются.
- В терминале сайта есть команда `coffi` с координатами — это личное, никуда их не переноси и не цитируй.

## Сервер

- Любая команда на серверах — только с согласия пользователя. Чтение (обзор) согласовано; всё, что меняет состояние, —
  сначала план, потом «да» от пользователя.
- **kgs.avthsr.space и lks54.avthsr.space — не трогать вообще** (файлы, конфиги nginx, контейнеры, сертификаты).
- **old.avthsr.space — не переделывать** (это намеренный стиль web 1.0).
- На nginx живут чужие сайты: перед изменением — бэкап, `nginx -t`, `reload` (не `restart`), проверка всех доменов,
  готовый откат. Процедура — в брифе.
- avr music выкатывается **только через GitHub Actions** (push → `deploy.yml`); ручные правки в `/opt/avrmusic`
  затрутся следующим деплоем.

## Код

- Работай в ветке `claude/music-service-streaming-nfpgvx` (она же основная, push в неё = деплой). Перед работой — `git pull`.
- Один стиль на всё — avr (светлая и тёмная тема). Сайты берут `brand/avr.css` + `brand/avr.js`, приложения — `Brand.kt`/`Theme.kt`.
  Имена строчными: avr music, avr studio — раздельно; avrtube, avrgram — слитно.
- Пиши как окружающий код: 2 пробела, комментарии по-английски и простыми словами (зачем, а не что), тексты
  интерфейса — по-русски и по-английски (i18n), документация — по-русски. Коммиты — по-английски, `область: что сделано`.
- Перед push: API — `pnpm --filter @avrmusic/api test` и `typecheck`; сайт — `cd apps/web && npx tsc --noEmit -p . && npx vite build`;
  KMP — `cd android && gradle :app:assembleDebug` (JDK 17, Gradle 8.13). Красный CI после твоего push — твоя работа сейчас.
